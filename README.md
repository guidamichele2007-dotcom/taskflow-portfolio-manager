# taskflow-portfolio-manager
AI-powered productivity platform that combines project management, intelligent task organization, portfolio generation, personal analytics, AI automation, and integrations into a single modern ecosystem.

## OmniLife

La progettazione della piattaforma mobile **OmniLife** — un ecosistema personale modulare e Offline-First — è documentata in nove livelli:

- **[Product Bible](docs/omnilife/product_bible/README.md)** (`docs/omnilife/product_bible/`) — il documento di riferimento assoluto: identità, missione, manifesto, strategia, principi e Product Constitution. Ogni decisione futura deriva da qui.
- **[Functional Bible](docs/omnilife/functional_bible/README.md)** (`docs/omnilife/functional_bible/`) — il comportamento completo e senza ambiguità di ogni modulo e funzione (153 funzioni specificate), tracciato ai principi, Jobs To Be Done e decisioni della Product Bible.
- **[UX Bible](docs/omnilife/ux_bible/README.md)** (`docs/omnilife/ux_bible/`) — l'esperienza utente completa: architettura informativa, navigazione, inventario schermate, flussi, microinterazioni, gesti, stati vuoti, errori, onboarding, accessibilità e una UX Constitution di 312 regole.
- **[Data Model Bible](docs/omnilife/data_model_bible/README.md)** (`docs/omnilife/data_model_bible/`) — il modello dati concettuale completo: 26 entità con attributi, relazioni, ownership, ciclo di vita, versionamento e sincronizzazione logica, senza scegliere database o API.
- **[Technical Architecture Bible](docs/omnilife/technical_architecture_bible/README.md)** (`docs/omnilife/technical_architecture_bible/`) — l'architettura logica completa: 6 layer, 15 moduli/servizi, boundaries, event-driven architecture, plugin architecture, offline-first, sicurezza architetturale — indipendente da ogni linguaggio, framework, database o cloud provider.
- **[Design System Bible](docs/omnilife/design_system_bible/README.md)** (`docs/omnilife/design_system_bible/`) — il sistema di design completo: token visivi (tipografia, colore, spaziatura, elevazione), linguaggio visivo, motion, stati, accessibilità visiva e una libreria di 21 componenti — indipendente da ogni tecnologia di rendering (nessun mockup, CSS o codice).
- **[Engineering Plan](docs/omnilife/engineering_plan/README.md)** (`docs/omnilife/engineering_plan/`) — il piano eseguibile di sviluppo: 16 Epic, ~42 Feature, 158 Story tracciate agli ID della Functional Bible, dipendenze, percorso critico, roadmap tecnica e pratiche di ingegneria (branching, code review, testing, release, rollback) — senza ancora scegliere linguaggio, framework, provider cloud o database fisico.
- **[Technology Decision Record](docs/omnilife/technology_decision_record.md)** (`docs/omnilife/technology_decision_record.md`) — la prima scelta tecnologica reale: 18 decisioni (linguaggio mobile, backend, sincronizzazione, database locale/server, storage, notifiche, analytics, sicurezza, CI/CD, ecc.), ciascuna con almeno 3 alternative confrontate e motivate contro tutta la documentazione precedente. Ogni futura riga di codice deriva da questi otto documenti.
- **[Documentazione tecnica di progetto](docs/omnilife/README.md)** (`docs/omnilife/`) — visione, analisi, funzionalità, architettura, UX, requisiti, sicurezza, business, rischi e piano di sviluppo.

Il repository contiene inoltre l'infrastruttura di bootstrap del progetto — workspace Kotlin Multiplatform, moduli placeholder, app iOS/Android, backend Go, CI, lint — preparata secondo tutte le decisioni tecnologiche sopra e senza alcuna funzionalità di business. Vedi **[README-BUILD.md](README-BUILD.md)** per come è costruito il repository e **[Bootstrap Infrastructure Report](docs/omnilife/bootstrap_infrastructure_report.md)** per struttura, moduli e TODO del primo sprint.
